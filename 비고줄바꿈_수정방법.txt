[이 문서는 "확인기능_수정방법.txt" 를 먼저 적용한 다음에 고치는 것입니다]
  - 아래 줄 번호는 확인 기능까지 고친 상태의 파일 기준입니다.
  - 확인 기능을 아직 안 고쳤다면 줄 번호가 다릅니다. 그때는 줄 번호
    대신 "찾을 문구" 로 찾으면 됩니다. 고치는 내용은 같습니다.

[왜 지금은 줄바꿈이 안 되나요?]
  원인이 두 가지라서 둘 다 고쳐야 합니다.
  1) 입력칸이 한 줄짜리(<input type="text">)라서 Enter 를 눌러도 줄이 안 바뀝니다.
     → 여러 줄 입력칸(<textarea>)으로 바꿉니다.
  2) 줄바꿈을 저장해도, HTML 은 원래 줄바꿈을 공백 하나로 보여 줍니다.
     → CSS 의 white-space: pre-line 을 비고 칸에 붙여서 줄바꿈을 살립니다.
  일일업무의 "세부 내용" 칸이 이미 이 방법(textarea + pre-line)을 쓰고 있어서
  같은 방법으로 맞췄습니다.

[고치지 않아도 되는 것]
  - DB(db.py), app.py : 지금 비고 칸에 줄바꿈 글자도 그대로 저장됩니다.
                        DB 를 다시 만들 필요도 없습니다.
  - 엑셀(excel.py)    : 이미 모든 칸에 자동 줄바꿈(wrap_text)이 켜져 있어서
                        고치지 않아도 줄이 나뉘어 나옵니다.
  - 검색 결과         : 비고가 다른 내용과 한 줄로 이어 붙어 나오므로
                        줄바꿈이 공백으로 보이는 지금이 읽기 편해 그대로 둡니다.

[쓰는 방법이 달라지는 점]
  - 전에는 비고 칸에서 Enter 를 누르면 바로 등록됐지만, 이제 Enter 는 줄바꿈입니다.
    등록은 [분석중으로 등록] 버튼을, 수정은 [저장] 버튼을 눌러야 합니다.
    (그래서 칸 이름을 "비고 (Enter 로 줄바꿈)" 으로 바꿨습니다)
  - 입력칸 오른쪽 아래 모서리를 끌면 칸 높이를 늘릴 수 있습니다.

[수정할 파일 5개]
  1) templates/analysis.html       - 등록 폼 입력칸, 표 2곳
  2) templates/analysis_edit.html  - 수정 화면 입력칸
  3) templates/index.html          - 홈 화면 표 2곳
  4) templates/print_day.html      - 인쇄 화면 표 2곳 + 스타일 1줄
  5) static/style.css              - 스타일 1줄

[읽는 법]
  - [기존] 을 찾아서 [변경] 으로 바꾸면 됩니다.
  - 블록 위아래의 "-----8<-----" 줄은 구분선이니 입력하지 마세요.
  - 긴 줄은 바뀌는 부분만 [기존]/[변경] 으로 적었습니다.
    그 줄 안에서 그 부분만 찾아 고치세요.
  - 파일은 UTF-8 로 저장하세요.

 1-1. 등록 폼 - 비고 입력칸을 여러 줄 입력칸으로
----------------------------------------------------------------------
위치: 약 49행
찾을 문구: 비고<input

[기존]
-----8<-----
    <label class="field wide">비고<input class="inp" type="text" name="note"></label>
-----8<-----

[변경]
-----8<-----
    <label class="field wide">비고 (Enter 로 줄바꿈)<textarea class="inp" name="note" rows="2"></textarea></label>
-----8<-----

  설명: rows="2" 는 처음 보이는 칸 높이(2줄)입니다. 더 높게 하려면 숫자를 키우세요.
        <textarea> 와 </textarea> 사이에는 아무것도 넣지 않습니다
        (공백이나 줄바꿈을 넣으면 그게 기본값으로 들어갑니다).


----------------------------------------------------------------------
 1-2. 분석중 표 - 비고 칸에 class="note" 추가
----------------------------------------------------------------------
위치: 약 88행

-----8<-----

[변경]
-----8<-----
          <td>{{ a.case_notation }}</td><td class="note">{{ a.note }}</td>
-----8<-----

----------------------------------------------------------------------
 5-1. 스타일 한 줄 추가
----------------------------------------------------------------------
위치: 약 120행 다음
찾을 문구: td.detail {

[기존]
-----8<-----
td.detail { color: var(--muted); font-size: 14px; white-space: pre-line; }
-----8<-----

[변경]  (아래 한 줄 추가)
-----8<-----
td.detail { color: var(--muted); font-size: 14px; white-space: pre-line; }
td.note { white-space: pre-line; }                                       /* 분석현황 비고: 줄바꿈 그대로 */
-----8<-----

  설명: pre-line = 입력한 줄바꿈은 그대로 보여 주고, 칸이 좁으면 자동으로도 줄을 바꿉니다.
        세부 내용(td.detail)과 달리 글자색/크기는 바꾸지 않았습니다 (지금 비고 모양 유지).
  참고: 브라우저가 옛 CSS 를 기억해서 줄바꿈이 안 보이면 Ctrl+F5 로 새로고침하세요.

  □ [엑셀 다운로드] → 비고 칸이 여러 줄로 보임
  □ 예전에 한 줄로 쓴 비고는 그대로 한 줄로 보임

 [에러/이상할 때]
======================================================================
  - 등록 폼에 처음부터 빈 칸(공백)이 들어 있음
      → 1-1 의 <textarea ...></textarea> 사이에 공백/줄바꿈이 들어감. 붙여 쓰세요.
  - 수정할 때마다 비고 앞에 빈 줄이 늘어남
      → 2-1 의 {{ item.note }} 앞뒤에 공백/줄바꿈이 들어감. 붙여 쓰세요.
  - 입력은 여러 줄인데 표에서 한 줄로 보임
      → 그 화면의 <td class="note"> 가 빠졌거나, style.css 에 td.note 가 없음.
        인쇄 화면이면 print_day.html 의 <style> 에 td.note 가 있는지 확인 (4-1).
        그래도 안 되면 Ctrl+F5.
  - TemplateSyntaxError
      → {{ }} 나 따옴표 짝이 맞는지 확인.

 [테스트 결과] - 이 PC에서 확인한 내용
======================================================================
  - 위 내용을 실제 코드에 반영하고 자동 테스트 13개를 돌려 모두 통과했습니다.
      · 줄바꿈 넣은 비고 등록 → DB 에 줄바꿈 포함해서 저장
      · 등록 폼/수정 화면이 여러 줄 입력칸, 수정 화면에 기존 비고 그대로
      · 수정 저장 후에도 줄바꿈 유지
      · 분석현황 표, 홈 화면, 인쇄 화면에 class="note" 로 출력
      · 엑셀 비고 셀에 줄바꿈이 들어가고 자동 줄바꿈 켜짐
      · 검색 화면 정상
  - 앞서 만든 확인 기능 테스트(44개)도 다시 돌려 모두 통과했습니다.
  - 이 PC에는 Python 2.7 이 없어서 Python 3 + Flask 3.1 로 테스트했습니다.
    이번 수정은 HTML/CSS 만 바꾸는 것이라 Python 버전과는 상관이 없습니다.
  - 화면 모양(입력칸 높이, 버튼 위치)은 브라우저로 직접 보지는 않았습니다.
